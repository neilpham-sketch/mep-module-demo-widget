# Demo Widget — Agent Operating Instructions

This is `mep-module-demo-widget`, a MEP SaaS v2 module generated by the `mep` CLI. If
you are an AI coding agent (Claude Code, Codex, or any other AGENTS.md-aware tool) working
in this repo, read this file first — it is your entire orientation. No external plugin or
skill system is assumed; everything here is plain Markdown any agent can follow.

## What this repo is

- A pnpm workspace: `apps/internal` (this module's own NestJS backend) + `apps/external`
  (its public-facing counterpart, empty until you add customer-facing routes) + `apps/worker`
  (RabbitMQ CDC consumer) + `packages/ui` (Next.js UI component library, consumed by
  `mep-dashboard-fe`) + `e2e` (Playwright end-to-end tests).
- Module key: `demo-widget`. Module name: `Demo Widget`. See `module.manifest.json`
  for the full manifest (permissions, Kong route, delivery target).

## The workflow: Spec → Plan → Implement → E2E

Every feature in this repo goes through four short steps. Each has its own playbook —
read the relevant one before starting that step:

1. **Spec** (`docs/agent/spec.md`) — write down what you're building and why, before touching code.
2. **Plan** (`docs/agent/plan.md`) — turn the spec into a short, ordered task checklist.
3. **Implement** (`docs/agent/implement.md`) — build it, test it, commit it.
4. **E2E** (`docs/agent/e2e.md`) — run the Playwright suite before calling anything done.

This is intentionally lightweight — a single module built in ~48 hours does not need a
multi-day platform's brainstorming/ADR process. If a change turns out to need real
architectural discussion (a new deployment topology, a new cross-module data dependency),
stop and flag it instead of forcing it through this four-step flow.

## Hard constraints (do not violate these)

- **No route is permission-guarded yet.** Do not import or invent a decorator for this —
  check `@prowerbdigital/common`'s actual current exports before adding real authorization.
- **The Kong route reservation is fixed.** This module is only ever reachable at
  `/demo-widget/api` — do not change `app.setGlobalPrefix(...)` in
  `apps/internal/src/main.ts`, and do not add routes outside that prefix.
- **Delivery is staging/dev only.** Nothing in this repo can reach production — there is
  no production CI job, by design. Do not add one.
- **Never commit secrets.** Only `.env.example` files are checked in. Real `.env`/`venv/.env.*`
  files are gitignored.

## Core commands

```bash
pnpm install
cp apps/internal/.env.example apps/internal/.env
cp apps/internal/venv/.env.example apps/internal/venv/.env.dev
cp apps/external/.env.example apps/external/.env
cp apps/external/venv/.env.example apps/external/venv/.env.dev
pnpm db:generate && pnpm db:migrate
pnpm start:dev          # boot apps/internal (default port 8080)
pnpm dev:external       # boot apps/external, in another terminal (default port 8081)
pnpm test               # this repo's own unit/structural tests, if any exist yet
pnpm typecheck
pnpm e2e                # Playwright suite — see docs/agent/e2e.md
```

See the root `README.md` for the full time-to-first-boot walkthrough.
